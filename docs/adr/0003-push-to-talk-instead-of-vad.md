# ADR 0003: Push-to-Talk Instead of Voice Activity Detection

## Status

Accepted

## Context

เฟสแรกจำลองการ "พูดแทรก" ผ่าน Demo Controls (ปุ่มข้อความจำลอง) ซึ่งไม่ใช่ประสบการณ์
เสียงจริง เฟสนี้ต้องการให้คุณครูถามคำถามด้วยเสียงจริงระหว่างบทเรียน มีสองแนวทางหลัก:
(1) Voice Activity Detection (VAD) ฟังตลอดเวลาแล้วตรวจจับเมื่อมีคนพูด หรือ
(2) Push-to-Talk ให้ผู้ใช้กดปุ่มเองเพื่อพูด

## Decision

เลือก **Push-to-Talk** และ**ตัด VAD ออกทั้งหมด**:

- ผู้ใช้ต้องกดค้างปุ่มเพื่อพูด (Mouse/Touch/Keyboard)
- อัดเสียงเฉพาะช่วงกดค้างผ่าน `MediaRecorder`
- กดปุ่มแล้วหยุดเสียง AI ทันที (ไม่ต้องรอ AI พูดจบ)
- ไม่มี Logic ตรวจจับเสียงพูด/เสียงรบกวนจากไมโครโฟนที่เปิดค้างไว้

## Consequences

**ข้อดี**:

- Implementation ง่ายกว่ามาก ไม่ต้อง Tune VAD Threshold ที่มักพลาดทั้ง False
  Positive (เสียงรบกวนโดนตีความเป็นคำถาม) และ False Negative (พูดเบาไม่ถูกจับ)
- ผู้ใช้ควบคุมได้ชัดเจนว่าระบบกำลังฟังตอนไหน ลดความเสี่ยงเรื่อง Privacy (ไมค์ไม่ได้เปิด
  ฟังตลอดเวลา)
- ไม่ต้องเปิด Microphone Stream ค้างตลอด Session ประหยัด Resource/Bandwidth

**ข้อเสีย/ความเสี่ยงที่ยอมรับ**:

- ผู้ใช้ต้องเรียนรู้ Interaction แบบกดค้าง (ต่างจาก Assistant เสียงทั่วไปที่ฟังตลอด)
  บรรเทาด้วยการทำปุ่มเด่นชัดพร้อม Label สถานะ (`กดค้างเพื่อพูด` / `กำลังฟัง...` ฯลฯ)
- พูดแทรกกลางประโยคโดยไม่ได้ตั้งใจกดปุ่มก่อนจะไม่ถูกระบบรับรู้ (ตั้งใจ — ป้องกัน False
  Trigger)
- ไม่รองรับ Barge-in แบบ Real-time ที่บาง Product เสียงคาดหวัง (Trade-off ที่ยอมรับ
  เพื่อความเรียบง่ายและ Privacy)
